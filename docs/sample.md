# RAG 系统调优实践手册

## 一、什么是 RAG

检索增强生成（Retrieval-Augmented Generation，简称 RAG）是一种在生成答案前先从外部知识库检索相关片段，再把片段作为上下文交给大模型的技术方案。它的核心价值在于：让模型的回答有据可依，降低幻觉，并且知识更新无需重新训练模型。

一个典型的 RAG 流水线包含四个阶段：文档解析、分块（Chunking）、索引与检索、重排与生成。每个阶段的策略选择都会显著影响最终效果。

## 二、分块策略的选择

分块是 RAG 中影响最大的环节之一。块太大，噪声多、向量语义被稀释；块太小，上下文不完整、答案缺乏连贯性。

按 Token 固定切块是最常用的方式，粒度可控，配合重叠（Overlap）可以缓解跨块的语义断裂问题。重叠比例通常设置在 10% 到 20% 之间，过小效果不明显，过大则索引冗余、成本上升。

按段落切块能够保留原文的自然结构，适合已经排版良好的文档，例如产品手册、规章制度。它的缺点是段落长度差异很大，短段落会导致向量稀疏，长段落又会超出模型的上下文窗口。

语义切块先计算相邻句子的向量相似度，在语义发生转折的地方断开。这样得到的块内部语义一致性最高，但代价是需要额外调用一次向量模型，建库成本更高。实践中通常设置一个 Token 上限，避免语义块无限膨胀。

递归分隔符切块是一种工程折中方案：先按空行切，切不动再按换行切，再按句子切，最后按 Token 切。它兼顾了结构完整性和长度约束。

## 三、检索：语义与关键词的取舍

纯语义检索擅长处理同义表述和模糊意图，例如用户问"怎么让回答更准"，资料里写的是"提升准确率的方法"，语义模型能够匹配上。但语义检索对精确字符串不敏感，例如型号编号、专有名词、错误码，向量往往区分不开。

BM25 是基于词频和逆文档频率的经典关键词算法。它对精确匹配非常敏感，且不依赖任何模型，速度极快。缺点是无法处理同义词和语义泛化。

混合检索把两者结合起来，是工业界的默认选择。融合方式有两种主流做法：RRF（倒数排名融合）只使用两路结果的排名，不需要关心分数的量纲，鲁棒性好；加权求和则先归一化再按权重相加，可解释性更强，但需要调权重。

## 四、重排的价值

向量检索为了速度，通常采用近似最近邻搜索，召回率高但排序精度有限。重排（Rerank）使用交叉编码器（Cross-Encoder）对查询和候选片段做逐对打分，精度显著高于双塔向量检索。

典型做法是：先用混合检索召回 20 到 50 条候选，再用重排模型精排，最后取 Top 3 到 Top 8 进入上下文。这个过程称为两阶段检索。

## 五、阈值与拒答

即使做了重排，也仍然存在检索不到相关内容的情况。设置一个相似度阈值，当最高分低于阈值时直接回复"依据当前知识库无法回答"，比让模型硬着头皮编造要可靠得多。

阈值的设置需要结合分数分布：如果使用重排模型的分数，0.3 到 0.5 是常见的起始点；如果使用归一化后的融合分数，则需要观察实际分布再定。建议在检索实验台上跑一批真实问题，观察命中与未命中的分界线。

## 六、问题改写

用户的问题往往不适合直接检索。例如多轮对话中的"它有什么缺点"，缺少主语；或者问题过长，包含大量无关修饰。

常见的改写手段有三种：单查询改写，把指代补全成独立完整的句子；多查询扩展，从多个角度生成若干查询分别检索再合并；HyDE，先让模型生成一个假设性答案，再用这个答案去检索，因为答案的表述方式往往更接近原文。

## 七、消费信贷场景的注意事项

在个人消费信贷领域落地 RAG 时，需要特别关注以下几点：监管规则文档的条款编号必须能被精确检索到，因此 BM25 不可缺席；产品要素表（利率、期限、额度）适合结构化存储后单独召回，而不是混在普通文本里；涉及用户个人信息的文档必须做好脱敏再进入索引，避免模型输出泄露隐私。
